## 1. News scraper: «топові новини для масової аудиторії» + персональне → Telegram

### 1.1 Проблема
`rank.ts` зараз оптимізований під одного читача. Формула:
```
0.30 · personal_relevance   ← вузькі keyword-и (vibe coding, Claude Code, твоя кар'єра)
0.18 · HN points  0.14 · Reddit  0.14 · mentions  0.10 · InBrief  ...
```
`NEGATIVE_KEYWORDS` штрафують геополітику, бізнес, дослідження — саме те, що дає
**найбільший трафік** у широкому AI-сегменті (релізи моделей, раунди фінансування,
«AI забере роботи»). Для масової аудиторії ця логіка інвертована.

### 1.2 Рішення — два незалежні pipeline-и з одного fetch-пулу

```
                         ┌─────────────────────────────┐
   fetch (спільний)  ──► │  raw articles (Supabase)     │
   HN+Reddit+RSS+      │  │  + нові джерела (див. нижче) │
   InBrief             │  └──────────────┬──────────────┘
                       │                 │
          ┌────────────┴───────┐   ┌─────┴───────────────┐
          │ rank-public        │   │ rank-personal       │
          │ (масова аудиторія) │   │ (твій профіль = as-is)│
          └────────┬───────────┘   └─────────┬───────────┘
                   │                          │
        summarize → publish → САЙТ      summarize-short → TELEGRAM (твій канал)
```

**A. Public ranking (`rank.ts` → дефолт для сайту)** — нова формула без персонального шару:
```
0.30 · engagement_velocity   // (HN+Reddit) / години_від_публікації — ловить вірусне рано
0.22 · cross_source_mentions // скільки джерел покрили = «велика новина»
0.18 · source_authority      // OpenAI/Anthropic/Google/Meta blog, TechCrunch, The Verge > рандом
0.15 · recency_decay         // експоненційне згасання за 48 год
0.10 · inbrief_importance    // редакційний сигнал (вже є)
0.05 · topic_breadth_bonus   // бонус категоріям масового попиту (releases, business, research)
```
- Прибрати `POSITIVE_KEYWORDS` персонального профілю; лишити **тематичний gate** «це про AI?»
  (інакше в топ полізе загальний tech-шум).
- `NEGATIVE_KEYWORDS` пом'якшити: **не штрафувати** business/funding/policy — це трафік-драйвери;
  лишити фільтр відвертого спаму/clickbait/дублів.
- Підняти вибірку з top-10 до **top-12…15** (більше карток на головну).

**B. Personal ranking (`rank-personal.ts`)** — поточна `rank.ts` логіка **без змін**,
але виносимо в окремий модуль. Результат не йде на сайт, а:
1. `summarize` у скороченому форматі (тільки `title`, `why_matters`, `social_hook`, лінк);
2. постимо в **твій Telegram-канал** через Bot API (новий модуль `publish-telegram.ts`).

**C. Telegram-постинг (`pipeline/publish-telegram.ts`)** — новий стейдж:
- Env: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`.
- Формат поста: жирний заголовок → 1-2 речення «чому важливо» → лінк → теги.
- Запуск з того ж GitHub Action (додати крок після `run-daily`), або окремий cron.
- Це безкоштовний канал дистрибуції + твоя персональна стрічка зберігається.

### 1.3 Нові джерела (для широти й авторитетності)
Додати в `fetch.ts` (модулі в `pipeline/sources/`):
- **Офіційні блоги:** OpenAI, Anthropic, Google DeepMind, Meta AI, Mistral, xAI (RSS/Atom).
- **Tier-1 медіа:** TechCrunch AI, The Verge AI, VentureBeat AI, Ars Technica (RSS).
- **GitHub Trending** (AI/ML repos) — сигнал «що будують прямо зараз».
- **Product Hunt** (AI-категорія) — нові продукти = «tools» трафік.
- **arXiv (cs.AI/cs.CL/cs.LG)** — для «research» категорії, з importance-фільтром.
- **X/Twitter** (опціонально, через nitter/API) — найшвидший сигнал, але крихкий.

## 2. База даних: чому **Supabase (Postgres) + pgvector**, а не Notion

### 2.1 Вердикт
**Залишаємось на Supabase. Notion як сховище контенту для публічного продукту — глухий кут.**
Код уже на Supabase — це не міграція, а підтвердження курсу + кілька доповнень.

### 2.2 Чому не Notion (для комерційного трафіку)
| Критерій | Notion API | Supabase / Postgres |
|---|---|---|
| Rate limits | ~3 req/s — вб'є на першому сплеску трафіку | пул з'єднань, read-репліки |
| Запити | немає SQL, лише прості фільтри | повний SQL, JOIN, FTS, faceted search |
| Пошук | примітивний | вже маєш FTS (`010_search_fts`) + facets (`014`) |
| Семантика | немає | **pgvector** — дедуп, «схожі новини», рекомендації |
| Latency для SSR/SEO | високий, нестабільний | низький, кешований |
| Вартість при масштабі | дорожчає на seats/API | передбачуваний, є free tier |
| Multi-tenant / premium | немає auth-моделі | RLS + Supabase Auth «з коробки» |

> Notion лишаємо лише як **внутрішній editorial/CMS-інструмент** (ручні правки, контент-календар,
> ідеї спонсорів) — через уже підключений Notion MCP. Але **не** як прод-сторедж для сайту.

### 2.3 Що додати до Supabase
1. **pgvector extension** + `articles.embedding vector(768)`:
   - семантичний дедуп (краще за Jaro по заголовку);
   - блок «Схожі новини» на `ItemPage` (engagement ↑, pageviews/session ↑);
   - персональні рекомендації для залогінених (основа premium-фічі).
2. **Auth + профілі** (`profiles`, `subscriptions`) — підписники, premium-тіри, saved items.
3. **Events-таблиця** (`events`: view/click/share) — власна аналітика для спонсорів
   (показуємо рекламодавцям реальні CTR/impressions → це і є продукт для них).
4. **`sponsors` / `ad_slots`** — нативні рекламні вставки в брифі (див. §4).
5. **Партиціонування `articles` по місяцях** + retention-політика (raw старше 90 днів → cold).
6. **Materialized views** для головної (топ дня, топ тижня по категоріях) → миттєвий рендер.
7. **Edge Functions** (Supabase) для: підписка на email, Telegram webhook, Stripe webhook.

### 2.4 Робота
- [ ] `enable extension vector;` + міграція embedding-колонки + backfill через Gemini embeddings.
- [ ] Auth + `profiles`/`subscriptions` міграції + RLS-політики.
- [ ] `events` + клієнтський трекер (доповнити `lib/analytics.ts`).
- [ ] Materialized view `homepage_top` (refresh після `publish`).

## 3. Дизайн головної сторінки AI Scrapper

> **Принцип розділення (підтверджено кодом):** головна (`TodayPage`) — це **кураторська
> вітрина** (магазинна полиця). Список з сайдбаром фільтрів — це вже `NewsPage`
> (`/:lang/news`), він **лишається окремим** і не змінюється структурно. Головна веде на нього.

### 3.1 Топ-6 категорій для головної (з 9 наявних — обираємо масові)
Поточні 9 категорій заточені під dev-нішу. Для **масової аудиторії** просуваємо на головній
6 «вітринних» рубрик (мапимо на наявні slug-и + 1-2 нові для широти):

|---|---|---|---|
| 1 | **Models & Releases** — GPT/Claude/Gemini/Llama релізи | №1 трафік-драйвер у всьому AI | `models-and-research` + `tools-and-releases` |
| 2 | **AI Tools & Products** — застосунки, агенти, IDE | широкий попит, affiliate-потенціал | `tools-and-releases` + `agents-and-mcp` |
| 3 | **Business & Funding** — раунди, угоди, M&A | founders/інвестори, висока CPM реклами | *нова* `business-and-funding` |

## 4. Монетизація: брейншторм, конкуренти, фічі, фінальний план

### 4.1 Карта конкурентів

| Конкурент | Формат | Монетизація | Що вкрасти | Їхня слабкість (наш шанс) |
|---|---|---|---|---|
| **TLDR AI** | email-дайджест | спонсорство (~$X тис/випуск) | формат «scannable», сегментовані випуски | лише email, слабкий сайт/SEO/архів |
| **The Rundown AI** | email + курси | спонсорство + **AI University (курси)** | освітня монетизація, growth-loops | мало dev-глибини |
| **Ben's Bites** | email + community | спонсорство + Pro-ком'юніті | community/Discord, job board | контент тонкий |
| **Smol AI (AINews)** | email | спонсорство | **глибина для інженерів**, агрегація Discord/HN | UX/дизайн слабкий |
| **Superhuman AI** | email | спонсорство | мемна подача, retention | немає вертикалі |
| **InBrief.info** | сайт + архів | ? (наше джерело!) | curation + importance_score | (вже інтегровано як джерело) |
| **Futurepedia / There's An AI** | каталог тулів | affiliate + listing fees | **каталог AI-тулів = affiliate-машина** | не новини |

**Наш диференціатор:** єдиний, хто поєднує **(a)** широкий топ-дайджест (масовий трафік),
**(b)** глибоку **dev/vibe-coding вертикаль** (moat проти TLDR/Rundown), **(c)** **білінгву EN/UK**
(недообслужений UA/CEE-ринок), **(d)** мультиформат (сайт + email + Telegram + автошортси).

### 4.2 Фічі, які «перетягуємо» в конкурентів
1. **Сегментовані email-випуски** (TLDR): загальний + «Dev edition» + «UA edition».
2. **AI Tools Directory** (Futurepedia): каталог тулів з `tools_mentioned` → affiliate-лінки.
   У нас уже накопичуються згадки інструментів — це готова data-перевага.
3. **Курси/освіта** (Rundown): «AI for Devs» / «Prompt Engineering» — продаж знань.
4. **Community/Job board** (Ben's Bites): Telegram/Discord + AI-вакансії (listing fees).
5. **Inженерна глибина** (Smol): наш `deep_dive` (500 слів оригінального аналізу) вже б'є всіх.
6. **Автогенеровані шортси** (ніхто не робить системно): `video_script` вже генерується →
   YouTube Shorts/TikTok/Reels автопайплайн → найдешевший growth-канал.

### 4.3 Потоки доходу (за порядком запуску)
1. **Newsletter-спонсорство** (швидкий $, потрібно ~2-5k підписників):
   нативний `ad_slot` у брифі + email. Продаємо impressions/CTR з власної `events`-аналітики.
2. **Premium / Pro** ($5-9/міс): без реклами, повний архів, семантичні рекомендації,
   «Dev deep-dives», ранній доступ, експорт. (Stripe + Supabase Auth + RLS.)
3. **Affiliate** (AI Tools Directory): реферальні лінки на тули/курси/API-кредити.
4. **Data/API** (B2B): структуровані AI-новини з importance_score + ембедингами як API/feed.
5. **B2B intelligence** (high-ticket): кастомні галузеві дайджести для компаній.
6. **Sponsored deep-dives / job board** — додаткові, коли є аудиторія.

### 4.4 Growth (агресивний)
- **SEO як фундамент:** кожен `ItemPage` = оригінальна 500-слівна стаття + slug + SEO-поля
  (вже є) → довгий хвіст ключів «X explained», «how to use Y». Sitemap уже генерується.
- **Programmatic SEO:** концепт-хаби (`/concepts/:slug` вже є) + «X vs Y» сторінки.
- **Автошортси** з `video_script` → 1-3 кліпи/день на YouTube/TikTok/Reels.
- **Telegram + X-автопостинг** з `social_hook` (вже генерується) — щоденні дотики.
- **Email loop:** capture на головній (§3) → щоденний бриф → referral-програма.
- **UA-ринок:** білінгва EN/UK дає недоконкурентний україномовний сегмент безкоштовно.

### 4.5 Метрики (KPI-воронка)
`Impressions (соц/SEO) → Site sessions → Email subs → DAU/retention → Sponsorship CPM → Premium MRR`

## 7. Чому Beehiiv + Resend

- **Beehiiv** — побудований саме під монетизовані newsletter-стартапи: вбудована **ad-network**
  (легше знайти першого спонсора), **referral-програма** (growth-loop із §4.4), сегментація
  випусків (загальний / Dev / UA), вбудована аналітика open/CTR (потрібна спонсорам), безкоштовний
  старт. Це найкоротший шлях до §4.3-потоку №1 (спонсорство) без власної інфри.
- **Resend** — для **транзакційних** листів із Supabase Edge Functions (підтвердження підписки,
  premium-квитанції) — dev-friendly API, дешево, повний контроль.
- Альтернативи відхилено: ConvertKit/Mailchimp — дорожче й слабша монетизація; чистий самохост —
  забагато інфри/делайверабіліті-ризику на старті.

> Інтеграція: форма `EmailCapture` на головній → Beehiiv API (підписка) + Resend (double-opt-in).
