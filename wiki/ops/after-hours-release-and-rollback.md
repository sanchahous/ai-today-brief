## 1. Реліз-нотатка: що змінилось для читача

Реліз редизайну **After Hours v3** переносить публічний інтерфейс `aitodaybrief.com` на нову редакційну дизайн-систему, зберігаючи швидкість завантаження, повну доступність без JavaScript та нульовий ризик для даних читачів. (source: [after-hours-redesign-epic](../product/after-hours-redesign-epic.md) §1.1)

### 1.1 Візуальний стиль та типографіка
- **Нові кольорові теми Night та Day**: глибока нічна тема (Night) та вивірена денна палітра (Day) із гарантованим коефіцієнтом контрасту WCAG 2.2 AA (не менше 4,5:1 для основного тексту).
- **Редакційна типографіка**: акцентна гарнітура Fraunces для англійських заголовків, класична Georgia для українських заголовків (D4) та системно оптимізований гротеск Inter для основного тексту й інтерфейсних елементів.
- **Мінімальний розмір шрифту 12 px**: усунено надто дрібні написи; повна підтримка масштабування тексту до 200% без накладання блоків та спотворень.
- **Новий бренд-знак (Brand Mark)**: фірмова графічна плакетка зі знаком у формі літери A та акцентною крапкою celadon на сайті, у favicon, додатках та соц-ассетах (D7).

### 1.2 Навігація та пошук
- **Дворівнева шапка (Desktop Editorial Header)**: розділення глобальної навігації та актуальних випусків; компактний sticky-режим при прокручуванні сторінки вниз.
- **Мобільне меню (Sheet)**: зручна бічна шторка з швидким доступом до рубрик новин, категорій та пошуку.
- **Єдиний діалог пошуку (SearchDialog)**: викликається комбінацією `Ctrl+K` / `Cmd+K` або кнопкою пошуку в шапці; містить підказки популярних запитів (trending), клавіатурну навігацію та фокус-пастки.
- **Виділена сторінка пошуку `/[lang]/news/search`**: окремий хаб для детального перегляду знайдених публікацій із фільтрацією за темами (Topics) та релевантністю.

### 1.3 Читання та контентні хаби
- **Стрічка новин і фільтрація**: фасетні фільтри за категоріями та темами (`topics`), сортування (Newest, Oldest, Relevance) зі збереженням стану в URL без втрати серверного кешування.
- **Оновлені картки матеріалів**: структурні картки `StoryCard` та `DigestCard` з чіткою ієрархією метаданих, автором, часом читання та адаптивними прев'ю.
- **Evergreen-хаби**: концептуальні розділи Concepts, Guides та Category з вичерпними картками та зв'язками між темами.
- **Розділ AI Toolbox**: оновлений шелл для інструментів розробника (Prompt Optimizer, Settings Builder, CLAUDE.md Generator) із роботою виключно на стороні клієнта без надсилання коду на сервер.

### 1.4 Довіра, підписка та взаємодія
- **Форми підписки без нав'язливих модалок**: вбудовані форми `NewsletterForm` (інлайн, банд та на сторінці `/subscribe`) з чіткими станами відправки, валідацією та захистом від повторного кліку.
- **Делікатна картка згоди з кукі (Consent Card)**: компактне повідомлення у футері без перекриття контенту, з можливістю змінити вибір у будь-який момент.
- **М'який рух Tension v3**: плавні анімації переходів (View Transitions) та поява елементів; повна повага до налаштування операційної системи `prefers-reduced-motion` (миттєве перемикання без анімацій).

## 2. План відкату (Rollback Plan)

### 2.1 Загальна стратегія відкату
Якщо після релізу в production виникають непередбачені критичні дефекти (масові 5xx помилки, порушення SEO-індексації або збої ключових користувацьких шляхів), відкат здійснюється за чіткою ієрархією:
1. **Рівень 0 (Негайний, < 1 хв)**: Vercel Instant Rollback на попередній стабільний деплой.
2. **Рівень 1 (Кодовий)**: покроковий revert pull-реквестів у репозиторії у зворотному порядку фаз (фази 7 → 1).
3. **Рівень 2 (Токени)**: відкат дизайн-токенів окремим виділеним PR задля збереження компіляції та уникнення дрейфу CSS-змінних.

(source: [after-hours-redesign-epic](../product/after-hours-redesign-epic.md) §AH-7.4)

### 2.2 Негайний відкат інфраструктури: Vercel Instant Rollback
- **Коли застосовувати**: помилки виконання рантайму 5xx, падіння SSR, критичний збій кешування або пам'яті.
- **Порядок дій**:
  1. Відкрити Vercel Dashboard проєкту `ai-today-brief` → розділ **Deployments**.
  2. Знайти останній стабільний deployment до релізу After Hours v3 (коміт перед стартом релізного мерджу).
  3. Натиснути меню дій (`...`) → вибрати **Instant Rollback**.
  4. Або через Vercel CLI у терміналі:
     ```bash
     vercel rollback [DEPLOYMENT_ID]
     ```
  5. Перевірити доступність сайту за адресою `https://aitodaybrief.com/en`.

### 2.4 Токени — окремий виділений PR
Вимога картки AH-7.4: відкат дизайн-токенів оформлюється **окремим PR** після відкату споживачів (або в ізольованому пакеті).
- **Причина**: токени у `src/lib/design-system/tokens.ts` та змінні в `src/app/globals.css` формують базовий CSS-контракт. Відкат токенів у спільному масовому коміті спричинить помилки лінтера `tokens:check` та порушення компіляції Tailwind v4.
- **Вміст виділеного PR**:
  1. Повернення константи `TOKENS_VERSION` до вихідного значення.
  2. Відновлення базової палітри CSS-змінних.
  3. Запуск верифікації контрасту: `npm run tokens:check`.
  4. Запуск перевірки нерозпізнаних значень: `npm run design:raw:check`.

### 2.5 Безпека бази даних та збереження даних
- **Інваріант I-7 дотримано**: під час усього епіку After Hours v3 не вносилося жодних незворотних змін у схему Supabase (не додавалися обов'язкові колонки, не змінювалися таблиці статей чи профілів).
- Відкат коду не зачіпає стан бази даних і не спричиняє втрати читацьких даних чи історії публікацій. (source: `.cursor/rules/00-core.mdc` §Supabase; інваріант I-7)
